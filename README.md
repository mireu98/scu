## 웹 접근성 개선 내용 정리

1. **컬러 의존성 제거 및 상태 안내 보완**
   - **개선 전**: 오류 발생 시 입력창 테두리 색상(`has-error`) 변화만 주어 색각 이상 사용자가 오류를 인지하기 어려웠음.
   - **개선 후**: 색상 변화와 함께 명확한 텍스트 오류 문구 `error-message`와 스크린 리더용 `aria-live="polite"` 속성을 부여하여 시각 및 청각적 피드백을 동시에 제공하도록 개선.

2. **버튼 및 토글 상태의 시맨틱 마크업 (`aria-pressed`) 적용**
   - **개선 전**: 다크모드 전환 버튼이나 찜하기 버튼이 단순 텍스트 변경만 이루어져 스크린 리더 사용자가 현재 토글의 활성/비활성 상태를 알 수 없음.
   - **개선 후**: `aria-pressed="false/true"` 속성을 동적으로 제어하도록 구현하여, 보조기기 사용자가 버튼의 현재 선택(눌림) 상태를 정확히 이해할 수 있게 개선.

3. **입력 요소의 대체 텍스트 및 접근성 라벨 강화**
   - **개선 전**: 일부 폼 입력창에 레이블 연결이 누락되거나 아이콘 이미지의 대체 텍스트(`alt`)가 부실했음.
   - **개선 후**: 모든 `input` 및 `fieldset` 요소에 명확한 `label`과 `legend`를 매칭하고, 서비스 로고 이미지에 상세한 `alt` 속성을 작성하여 정보 전달력을 높임.

4. **테스트**
  - 테스트 1: 신작 게임 입점 신청 폼에서 아무것도 입력하지 않고 '입점 신청하기'를 누르기. >> 개발사 이름, 게임 이름, 플랫폼 선택 에러 문구가 각각 뜨며 제출이 막힘 && 인풋에 포커스를 잡아줘 사용자가 무엇을 해야할지 알려줌.

  - 테스트 2: 다크 모드 버튼이나 찜하기 버튼을 누른 후 브라우저 개발자 도구로 요소를 확인하기. >> aria-pressed="true"로 속성이 동적으로 변해 있는 것을 확인가능.
